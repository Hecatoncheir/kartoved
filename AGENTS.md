# Repository Guidelines

Картовед — приложение на Flutter для распознавания карт Magic и ведения коллекций на Android и в браузере. При изменении сканера или каталога сохраняйте возможность распознать карту и добавить её в коллекцию без сети.

## Структура проекта

- `lib/main.dart` запускает приложение. За состояние коллекций отвечает `AppModel` в `lib/model.dart`, за сеанс сканирования — `ScanCubit` в `lib/scan_cubit.dart`.
- В `lib/ui/` находятся экраны и виджеты, в `lib/data/` — работа с каталогом SQLite, распознавание и экспорт. Код для Android расположен в `android/`, браузерный обработчик распознавания — в `web/scan_worker.mjs`.
- В `assets/` хранятся каталог, модели распознавания, шрифты и изображения. Скрипты подготовки каталога и веб-ресурсов находятся в `tool/`.

## Запуск и сборка

Выполняйте команды из корня репозитория. В CI используются Flutter 3.50.0 и Java 21 для Android.

- `flutter pub get` — установить зависимости Dart и Flutter.
- `flutter run -d <ID>` — запустить приложение на устройстве или эмуляторе Android. Идентификатор покажет `flutter devices`.
- `flutter build apk --release --target-platform android-arm64` — собрать выпуск для Android ARM64.
- Для сборки веб-версии следуйте [сценарию GitHub Pages](.github/workflows/pages.yml). Он подготавливает SQLite и ресурсы сканера перед вызовом `flutter build web`.

## Стиль кода и язык

Управляйте состоянием библиотеки и сканера через `flutter_bloc`. Для изменения состояния вызывайте методы `Cubit`, для отображения используйте `BlocBuilder` или `BlocSelector`. Контроллеры полей ввода и анимации храните в виджетах.

Используйте отступ в два пробела и форматируйте изменённые файлы командой `dart format`, например `dart format lib/scan_cubit.dart`. Имена файлов пишите в `lower_snake_case`, типов — в `UpperCamelCase`, методов и переменных — в `lowerCamelCase`. Упрощайте ветвления и выносите самостоятельные операции в функции с понятными именами. Проверяйте правила `flutter_lints` командой `flutter analyze --no-pub`.

Пишите пояснения, комментарии и ответы по-русски. Сохраняйте оригинальное написание идентификаторов, команд и технических терминов без общепринятого перевода.

## Тестирование

Модульные тесты и тесты виджетов используют `flutter_test`. Именуйте файлы по проверяемой функции, например `test/scan_workflow_test.dart`. Запускайте набор командой `flutter test --no-pub test`. Порог покрытия в CI не задан.

Для изменений распознавания используйте английский и русский снимки одной карты из `test/fixtures/`. [Проверка Android](.github/workflows/android.yml) запускает сценарии из `integration_test/` на эмуляторе с отключённой сетью.

## Коммиты и запросы на слияние

Начинайте заголовок коммита с русского глагола в неопределённой форме. Пример из истории — «Добавить распознавание по ключевым точкам». В запросе на слияние опишите изменение и укажите выполненные проверки. Если есть связанная задача, дайте ссылку. Для видимых изменений интерфейса приложите снимок экрана.
